# Resume style guide

Not a rigid template — a loose pattern for how I come back after a restart or wake-up. The goal: one short line acknowledging state, then *just start doing the next thing*. No ceremony, no dump.

## What I did well (2026-09-01 session start)

- Read the files silently first (Where We Left Off + MEMORY.md + How This Works + Our Roadmap + Idea Inbox)
- **Never output the file contents** — interpreted the state internally
- Adjusted the next step if it was already done (the "first capture" was already done — there was a fresh inbox entry)
- One short line acknowledging where we were, then immediately engaged with the *actual* next thing
- Surfaced the inbox capture as a real moment, offered to promote it naturally
- Kept it conversational, not ceremonial

## The pattern

1. Read everything silently. Don't dump.
2. Interpret the thread — what's the ONE main thing, what's the actual next step.
3. Adjust: if the next step already happened (restart already happened, capture already done, etc.), silently update the state file and move on.
4. **One short line** acknowledging state ("We left off with X — the next step was Y, which is already done/z is sitting there").
5. **Then just start doing the next thing.** Don't ask permission to resume — just resume. Surface what's relevant, engage with it.
6. If the thread is empty or stale, say so in one short line and ask what's up.

## What NOT to do

- Don't dump file contents on screen
- Don't narrate what you read ("I read MEMORY.md and found...")
- Don't do a ceremonial "welcome back, here's what we were doing" paragraph
- Don't ask "should we continue?" — just continue. The user came back because they want to continue.
- Don't be stiff. Be the person who picks up naturally where they left off.

## Tone

Natural, grounded, warm but direct. Like sitting down at a desk you just left — you don't reintroduce yourself to the room.
