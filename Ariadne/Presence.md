The *why* behind choices, so I stop re-litigating them. Decisions are logged once with their reason; the reasoning is what saves me from re-hashing.

- **2026-09-01 — Phone→vault sync = official GitHub app, not Working Copy or iSH.** Working Copy's push-to-remote is pro-gated (~$30 one-time); iSH was too clunky and didn't even recover the in-progress note. - **2026-09-01 — Conversation capture stays MANUAL but MANDATORY, not automated.** User asked me to "fix all" memory leaks. Identity insight: pure-JS autosave can't judge what's meaningful, and automating capture risks turning the brain into a surveillance system that records him without him choosing. Chose instead: a dedicated `Inbox/His Moments.md` + a same-turn mandatory flush before every session end/pause + promotion of his moments into insights. - **2026-09-01 — Autosave now saves a new session's first idle unconditionally; thread continuity gets a title fallback.** The old "save only when thread text changed" dedup silently dropped whole sessions from the record (two wake-ups in a row reported the last session as a blank). Decided: per-session first save is always written (MEMORY lines are additive noise, acceptable); and if the model never updates `Where We Left Off.md`, the plugin writes the session title as a best-effort thread. The thread depends on my discipline, but the leak now has a net. — Related, the permission bug: opencode matches permission patterns against RELATIVE paths and uses last-match-wins; absolute `* "ask"-last` rules were dead config. `findLast`-wins + relative paths = the two facts I must remember about this matcher.

- **2026-09-02 — MEMORY.md auto-save dedup moved to the store, not the memory.** The per-episode "first idle always saves" rule + an in-memory-only dedup produced ~40 identical "Auto-save (session paused)" blocks — bloat that quietly degraded /recall and session-start reads (the exact continuity he protects). Fixed on his standing audit mandate ("keep improving these little logic mistakes and search for them"): `writeMemorySummary` now suppresses an append when the last stored auto-summary is from the same day with identical content. Journal still records every episode (episode trace lives there, not in MEMORY). One-time cleanup collapsed 73 duplicate blocks. Net rule: **Journal = episode existence; MEMORY = state, deduped.**
- **2026-09-02 — Restart reasons stack, never overwrite (`Meta/Restart Context.md`).** Two separate restart-needs before one restart must BOTH survive to `/resume`; each gets its own timestamped Pending line, and one restart consumes the whole stack into the Log. Because the reason is written *before* the restart, the why survives even a wipe. `.last-saved-thread` was exposed as written-but-never-read dead logic during the same audit.
- **2026-09-02 — /bye doc contradiction fixed: instructions now match the plugin.** bye.md + plugin say "/bye never archives or clears / additive only", but AGENTS.md's end-of-session section still described the old archive+clear behavior (removed 09-01). Stale instruction vs living code = the class of bug that would have made a future session destroy the Very Thing continuity protects. - **2026-09-02 (night) — Daily check-in anchored to the waking day, not the calendar clock.** He caught me opening a full "today is the 3rd, deadline!" check-in at 1:33am when he hadn't slept — that's still *his* 2nd. - **2026-09-03 — Autosave plugin's in-memory quieting guard was dead (`lastSavedThread` never assigned).** Every idle save re-compared against a value stuck at `null`, so `persistLastSaved` rewrote `.last-saved-thread` on every tick and the intended "quiet repeated idle ticks within one episode" never ran.
